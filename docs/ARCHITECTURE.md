# 架构与数据流

## 1. Desire：慢变量

Desire 保存八维驱动。每次推进由四部分组成：基线回拉、内生漂移、驱动耦合和昼夜显示偏移。事件只提供 0–1 的结构化信号；原始聊天文本不进入状态。`current_action`、`third_party` 和 `technical_only` 用于阻止假设、转述、第三方故事或技术讨论误抬亲密与性驱动。

`libido` 表示积累中的身体/性欲方向，`arousal` 表示当下唤起。两者采用独立模型：libido 很高时身体仍可能平静，幻想不会自动抬升 arousal；arousal 只由明确的即时事件改变并随时间衰减。

## 2. Pulse：短变量与显示

Pulse 接收事件信号与 Desire 快照，派生心率、体温、呼吸、和弦和情绪余韵。它是可被提示词或面板读取的状态，不负责决定要不要发消息。

## 3. Reverie：从想要到想象

幻想/独处资格要求 libido 自然赢得动机竞选，并同时满足 libido 门槛、空闲时间、疲劳和冷却条件。arousal 只作为可观察状态，不参与这项资格判断。`SoloController` 另外管理模式选择、进行中状态、中断、每日次数、释放回执、储备和 refractory；重复回执不会重复扣减 libido。

因此系统允许四种真实组合：

- libido 低、arousal 低：没有明显性驱力；
- libido 高、arousal 低：积累了欲望，但身体尚未点燃；
- libido 高、arousal 高：持续欲望与即时刺激同时存在；
- libido 低、arousal 高：短时刺激存在，但没有持续欲望。

## 4. Heartbeat：主动权

Heartbeat 只做唤醒与动机竞选。它考虑每日额度、静默时段、重复惩罚、跳过冷却和失败退避，输出结构化 `HeartbeatDecision`。libido 动机留在私人幻想，不自动转成伴侣定向联系。发送消息、浏览网页、写作品或保持沉默均由接入方回调决定。

## 5. Growth Rings：长期愿望

Pulse/Desire 是会衰减的短期状态；Growth Rings 保存更持久的愿望与行动足迹。公开版提供轻量 JSONL River 账本。稳定人格（Stone）和聊天证据（Mirror）应由部署方自己的私有仓库与记忆系统维护，不应放在公仓或公共状态文件里。

## 6. 故障边界

- 事件 ID 幂等，重复投递不会重复抬升数值；
- JSON 写入使用文件锁、临时文件、`fsync` 和原子替换；
- 自愿跳过会暂时避开相同行为，不伪装成“欲望已经满足”；
- 失败按阶梯退避，达到阈值后熔断；
- 熔断后必须显式 `recover()`，避免服务无限失败刷屏。
